# My Learning Journey

A growing collection of interactive courses, generated as a static Docusaurus
site and deployed to GitHub Pages.

## Development

Requirements: Node.js 20 or newer and pnpm 10.26.0. With asdf installed, the
versions in `.tool-versions` are selected automatically.

```bash
pnpm install
pnpm serve
```

`pnpm serve` starts the development server with hot reload and does not require
a production build.

Create a production build in `build/`:

```bash
pnpm typecheck
pnpm build
pnpm preview
```

`pnpm preview` serves the generated `build/` directory exactly as it will be
deployed.

Installed/offline-enabled apps show a percentage and downloaded/total MB while an
update downloads. The Workbox worker excludes unchanged cached revisions and counts
streamed, uncompressed asset bytes (not compressed network traffic). It stays below
100% until caching completes, then offers the existing Refresh prompt. Reading can
continue during an update; failed installs leave the current version available.
Reload when online to retry a failed update.

The local PWA plugin preserves Docusaurus registration and the Refresh popup while
building a worker with progress reporting. Its cache name and revision keys match
the default worker, so existing cached assets can be reused.

Commit/date information lives in `deployment.json`, fetched separately by the
footer and excluded from precaching. Changing only deployment metadata no longer
changes every page or the service worker; actual content/shared-bundle changes
still invalidate their affected assets. Offline, the footer reports that deployment
info is unavailable. The first release of this change must still download changed
page and application assets; byte-progress UI is available after loading that release.

Run `node --test scripts/pwa-update.test.mjs scripts/pwa-worker.test.mjs` to check
changed-byte accounting, streaming progress, and the notice lifecycle.

## Add a course

The source folders mirror the Contents navigation: `docs/courses/`, `docs/books/`,
`docs/articles/`, and `docs/calculator/` are siblings, with `docs/index.mdx` as the Contents page.
Books and Calculator retain their existing `/courses/books/...` and
`/courses/calculator/...` public URLs through explicit slugs.
Articles has its landing page at `/courses/articles/`. James Clear's collection
lives in `docs/articles/james-clear/`; its existing `/courses/books/the-power-of-imperfect/...`
URLs remain unchanged so saved links continue to work.
The Articles homepage card shows a New badge until the visitor opens James
Clear's collection or any of its articles. This preference is stored in that
browser's local storage, not synced across devices, and resets when site data
is cleared. If storage is unavailable, the badge stays hidden and a warning is
logged to the browser console.

1. Create `docs/courses/<course-slug>/intro.md`.
2. Add `_category_.json` in that directory with its label, position, and intro
   document ID.
3. Organize lessons into Markdown or MDX files and subdirectories.
4. Add the course to the catalog in `docs/index.mdx`.

Navigation is autogenerated from `docs/`, so a new course does not require a
sidebar code change. Shared interactive React components belong in
`src/components/`.

### Sidebar scope

The main Contents menu shows level-1 categories and their level-2 items in
dropdowns. Selecting a level-2 item shows that item and all its level-3-and-below
descendants in the left sidebar. This boundary stays fixed while opening deeper
pages. The menu's level-2 links define the sidebar scopes for every content type
on desktop and mobile, with an All contents return link and no special metadata.

Courses, Books, Articles, and Calculator each retain a landing page. The Courses overview at
`/courses` describes each course in `docs/courses/intro.md`; update it when adding
a course. In the home sidebar, root
titles open these pages and their arrows expand the level-2 links; the Contents
dropdown includes each landing link inside its expandable root group.

## GitHub Pages

The workflow in `.github/workflows/deploy-pages.yml` installs dependencies with
pnpm, runs Docusaurus, and deploys the generated `build/` directory. In the
repository's **Settings → Pages**, set the source to **GitHub Actions**.
