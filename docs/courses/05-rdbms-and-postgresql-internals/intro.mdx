Your database cat approved the transaction. Two customers still bought the last
item. 🐱🐘 Learn which promises come from constraints, which come from isolation,
and which require your application to retry.

This course follows a small order system through relational design, concurrency,
physical storage, query execution, and production failure recovery. It targets
developers who know basic programming and want to reason about database behavior,
not memorize configuration knobs. SQL is introduced through runnable examples.

## Start with evidence 🧪

Use a **disposable PostgreSQL 17 database**. The course uses version-specific
PostgreSQL 17 documentation, not a claim that 17 is the latest release. Other
relational databases share many ideas but differ in isolation and storage details.

The [lab setup](./labs.mdx) provides a small schema and exact two-session steps.
Browser exercises work without a server; they are bounded teaching fixtures,
not query planners or full MVCC implementations.

## The MVCC model, with the important corrections

The [XID lesson](./02-concurrency/02-xid-visibility.mdx) directly follows three
questions: **A)** what identifies a transaction and a tuple version, **B)** what
makes a version visible to a snapshot, and **C)** how INSERT, UPDATE, and DELETE
change the version chain.

XIDs are not timestamps or commit order, and read-only transactions may never
receive a normal XID. Snapshot bounds and a captured in-progress set matter,
not a comparison with the reader's own XID. Commit/abort status, command IDs,
lock-only xmax, MultiXacts, and wraparound prevent the simplified formula from
being a full visibility implementation. PostgreSQL **also locks conflicting
writers**: Read Committed wait/recheck and Repeatable Read serialization failures
are explored in the [isolation lesson](./02-concurrency/03-isolation.mdx).

## Sources and verification scope

Topic coverage was inspired by
[Iamanshuaditya's PostgreSQL Internals Course](https://github.com/Iamanshuaditya/postgresql-deep-dive).
The explanations, examples, quizzes, and illustrations here are original; that
repository is a syllabus inspiration, not copied lesson text. PostgreSQL 17
documentation and version-matched source links provide the primary references.
The course adds relational foundations, application boundaries, a qualified
InnoDB comparison, security, and a restore/incident exercise around that core.

The disposable lab was checked against **PostgreSQL 17.11**. Its automated
two-session suite verifies visibility, write skew, serialization failure, row-lock
timeouts, deadlock detection, aborted deletion, and constraint failures. Storage,
planner, RLS, partition, and pageinspect examples were also executed, and an
isolated logical dump/restore recovered the seeded 20,000 orders.

The optional comparison's exact two-session schedule was separately verified on
**MySQL 8.4.11**, including the retained snapshot, current-row update, and rollback.
It is not part of the downloadable PostgreSQL suite or a full migration test.
Replication and PITR lessons teach mechanisms and design checks; a multi-node
failover or physical/PITR restore drill was **not performed**. No toy fixture
establishes production capacity or a recovery SLA. The database cat still needs
evidence before signing off on those promises. 🐱
