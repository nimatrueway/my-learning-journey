Your model prints a confident label. Did it use the voice, the motion, or just a familiar-looking background? Today you are the tester, not the model's publicist.

## The mission

Run a speech recognizer on your own short recording and an action classifier on your own short video. Change one input condition at a time, predict what should happen, then compare. An unchanged result is evidence too; this is not a contest to make every perturbation break the model.

Use a supported Python version such as 3.11 or 3.12 in a fresh environment. These examples run on CPU, including on a Mac; they do not require CUDA or MPS. Allow internet access and disk space for packages and pretrained weights. Inference can take longer on a laptop.

## Part 1: keep the words fixed

Make three genuine WAV files in your working directory, each about five seconds long. Say **“Please put the blue cup beside the window.”** in each. Export as WAV from your recorder; renaming an M4A file does not convert it.

1. `clean.wav`: close to the microphone, quiet room.
2. `far.wav`: across the room, otherwise similar conditions.
3. `noise.wav`: close again, with quiet background sound.

Use your own voice, with no private conversations in the background. These separate takes are a small exploratory comparison, not a controlled benchmark: delivery can change as well as microphone conditions. Keep the sentence and speaking pace consistent.

Run this as `transcribe.py`:

```python
import soundfile as sf
from transformers import pipeline

transcribe = pipeline(
    "automatic-speech-recognition",
    model="openai/whisper-tiny.en",
    device=-1,
)

for filename in ["clean.wav", "far.wav", "noise.wav"]:
    samples, sample_rate = sf.read(filename, dtype="float32")
    if samples.ndim == 2:
        samples = samples.mean(axis=1)
    if samples.size == 0:
        raise ValueError(f"Empty recording: {filename}")
    result = transcribe({"raw": samples, "sampling_rate": sample_rate})
    print(filename, repr(result["text"]))
```

The dictionary carries the actual sample rate with the samples. The pipeline uses `torchaudio` to resample when necessary. Do not manually relabel a 48 kHz recording as 16 kHz.

Compare each transcript with the eight-word reference, ignoring capitalization and punctuation consistently. Count substituted, deleted, and inserted words; divide their total by eight for word error rate. This tiny score describes these takes only. Write the actual error alongside it: losing “blue” matters differently from adding a polite filler.

## Part 2: show the model a real action

Record a **landscape clip at least two seconds long**, ideally at 30 fps, with the action underway from the beginning. Use an ordinary action such as clapping or waving; put it in `action.mp4`. Keep the person large enough to survive the center crop. R3D predicts one of 400 Kinetics action classes, not an arbitrary description of everything in your video.

Run this as `classify_video.py`. The loader chooses sixteen frames near timestamps spaced 1/15 second apart, using frame timestamps rather than assuming the camera's nominal rate. This short, approximately 15 fps input follows the [pretrained recipe](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.video.r3d_18.html) more closely than taking sixteen arbitrary consecutive frames from any camera. It is a single-clip experiment, not the original multi-clip benchmark protocol.

```python
import av
import torch
from torchvision.models.video import R3D_18_Weights, r3d_18

def load_clip(filename):
    frames = []
    timestamps = []
    start_time = None
    with av.open(filename) as container:
        for frame in container.decode(video=0):
            if frame.time is None:
                raise ValueError("Video has no usable frame timestamps")
            if start_time is None:
                start_time = frame.time
            elapsed = frame.time - start_time
            frames.append(torch.from_numpy(frame.to_ndarray(format="rgb24")))
            timestamps.append(elapsed)
            if elapsed >= 1.1:
                break
    if not timestamps or timestamps[-1] < 1.0:
        raise ValueError("Need at least one second of decoded video")
    targets = torch.arange(16, dtype=torch.float64) / 15
    times = torch.tensor(timestamps, dtype=torch.float64)
    nearest = (times[:, None] - targets[None, :]).abs().argmin(dim=0)
    if nearest.unique().numel() != 16:
        raise ValueError("Too few distinct frames; record at 30 fps")
    selected = torch.stack([frames[index] for index in nearest.tolist()])
    return selected.permute(0, 3, 1, 2)

weights = R3D_18_Weights.DEFAULT
model = r3d_18(weights=weights).eval()
print(weights.transforms())
frames = load_clip("action.mp4")
assert frames.shape[:2] == (16, 3)
assert frames.dtype == torch.uint8

variants = {
    "normal": frames,
    "reversed": frames.flip(0),
    "frozen": frames[8:9].repeat(16, 1, 1, 1),
}
for name, selected in variants.items():
    batch = weights.transforms()(selected).unsqueeze(0)
    assert batch.shape == (1, 3, 16, 112, 112)
    with torch.inference_mode():
        scores = model(batch).softmax(dim=1)[0]
    probabilities, indices = scores.topk(5)
    print(f"\n{name}: {tuple(selected.shape)} -> {tuple(batch.shape)}")
    for probability, class_index in zip(probabilities.tolist(), indices.tolist()):
        print(f"{weights.meta['categories'][class_index]}: {probability:.1%}")
```

The important boundary is **decoded `[T,H,W,C]` → transform input `[T,C,H,W]` → model input `[B,C,T,H,W]`**. Decoded RGB frames are `uint8` values from 0 to 255; the weights transform scales these to floating point, resizes, center-crops, normalizes, and reorders the axes. If you instead supply floating-point frames, use values from 0 to 1 before normalization.

## 🧪 Predict, then perturb

The script prints three rankings for the **same selected frames**:

| Input | What you removed or changed | What to inspect |
|---|---|---|
| Normal | Nothing | Is the action among the top five? |
| Reversed | Temporal direction | Do labels or scores change? |
| Frozen | Motion and most frame variation | Does an appearance-based guess survive? |

Before reading the results, predict which comparison should matter for your clip. Reversing clapping or another repeated action may preserve its class. Opening and closing are directional, but this classifier might not have your desired pair of labels. Inspect its available categories before interpreting an absent label as a failure.

A high softmax score is relative to these 400 classes, not a calibrated guarantee of truth. If all three rankings match, the action may be order-insensitive, the background may dominate, or this model may not use the distinguishing movement. **One unchanged clip cannot tell those explanations apart.** Try a second clip that separates them.

<details>
<summary>🤓 When the input contract fails (optional)</summary>

- Missing file: run the script from the directory containing your recordings.
- Too few distinct frames: use a longer, higher-rate clip rather than silently duplicating frames.
- Unexpected channel or time dimension: print the shape before the transform; it expects `[T,C,H,W]`, not `[C,T,H,W]`.
- Implausible labels: check the class list, crop, timing, and lighting before blaming model size.
- Audio imports fail: use a clean environment with compatible current PyTorch and Transformers packages; keep torch, torchvision, and torchaudio matched.

</details>
