# 8.4 — Decoding: greedy, beam, and the temperature dial ⏱️ ~10 min · folds are optional extra

## The hook

Your trained decoder never outputs a sentence. At every step it outputs a **probability distribution over the whole vocabulary** — fifty thousand numbers that sum to 1. Turning that stream of distributions into text is a separate algorithm, with its own knobs, and it is not trained.

Which means: the same model weights can give you a crisp translation, a bland repetitive paragraph, or a delightful hallucination about a cat exploding politely. Nothing changed but the search strategy.

**Things to try:**

1. **Greedy** never changes. Read its per-step probabilities: each one is the tallest bar available *at that moment*.
2. **Beam**: raise the width and watch the winning sentence change. Then notice how safe it is — beams reward high average probability, and high probability means unsurprising.
3. **Sampling**: set temperature to 0.3 and roll a few times, then 1.5 and roll again. Low temperature nearly reproduces greedy; high temperature eventually finds `exploded`, which the model rated at 4%.
4. **Sampling with top-k = 1** is greedy, whatever the temperature says. Good sanity check that these knobs interact.

## Greedy: fast, deterministic, myopic

Take the argmax at every step. One forward pass per token, no bookkeeping, fully reproducible.

The failure is structural: a locally best token can strand the model in a globally worse sentence. Picking a slightly-less-likely verb now might unlock a far better continuation, and greedy cannot know, because it never looks past this step. It is gradient descent's cousin, stuck in the first local optimum it meets.

## Beam search: keep several stories alive

Maintain the $k$ best partial sequences, expand them all, keep the best $k$ again. With $k = 4$ you carry four candidate sentences until the end, then return the highest-scoring one.

Two details decide whether it works:

- **Length normalization.** Sequence score is a sum of log-probabilities, and every extra token adds a negative number. Without dividing by length (or a length penalty), beam search systematically prefers short outputs — the classic "truncated translation" bug.
- **Diminishing, then negative, returns.** In machine translation, quality typically improves up to roughly $k = 4$–$10$ and then *degrades*. Larger beams find higher-probability sequences that are worse text: empty outputs, generic phrasing, repetition. This is known as the beam search curse, and it is evidence that the model's probability is a proxy for quality, not quality itself.

Beam earns its keep where a *correct answer exists* and you want the best shot at it: translation, speech recognition, grammar correction, structured generation. That is the encoder–decoder neighborhood from this module.

## Sampling: for tasks with many good answers

Draw from the distribution instead of maximizing it. Three dials do almost all the work:

- **Temperature $T$** reshapes the distribution before sampling. $T < 1$ sharpens toward the peak, $T > 1$ flattens it toward chaos, $T \to 0$ becomes greedy. It changes *how boldly* you choose.
- **Top-k** keeps only the $k$ most likely tokens and renormalizes. Simple, but a fixed $k$ is wrong in both directions: too permissive when the model is confident, too restrictive when it is genuinely uncertain.
- **Top-p (nucleus)** keeps the smallest set of tokens whose probabilities sum to $p$ (typically 0.9–0.95). The cutoff adapts to the model's confidence, which is why it became the default for open-ended text.

Add a **repetition penalty** when loops appear, and always set explicit stopping rules: `<eos>`, a maximum token count, and stop strings. Ignoring the long tail is the point of top-k and top-p — a 0.001% token is rare per step but nearly certain to appear somewhere in a thousand-token generation, and it is exactly the token that derails a paragraph.

## Tiny example: the same model, three personalities

```python
from transformers import AutoTokenizer, AutoModelForSeq2SeqLM

tokenizer = AutoTokenizer.from_pretrained("t5-small")
model = AutoModelForSeq2SeqLM.from_pretrained("t5-small")
inputs = tokenizer("translate English to German: the cat knocked the glass off the table",
                   return_tensors="pt")

greedy = model.generate(**inputs, max_new_tokens=32)
beam = model.generate(**inputs, max_new_tokens=32, num_beams=4,
                      length_penalty=1.0, early_stopping=True)
creative = model.generate(**inputs, max_new_tokens=32, do_sample=True,
                          temperature=0.9, top_p=0.95)

for name, output in [("greedy", greedy), ("beam", beam), ("sampled", creative)]:
    print(name, tokenizer.decode(output[0], skip_special_tokens=True))
```

Nothing above touches the weights. `generate()` is a search loop wrapped around the same forward pass, and every argument in it is a decoding decision. Note also which arguments are silently ignored: pass `temperature` without `do_sample=True` and it does nothing, because there is no sampling step to reshape.

<details>
<summary>🤓 The actual math (optional)</summary>

Temperature rescales the logits $z$ before the softmax:

$$P_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

- $T \to 0$ sends all mass to the largest logit — that is greedy
- $T = 1$ leaves the model's own distribution untouched
- $T > 1$ shrinks the gaps between logits, lifting the tail

Beam search ranks candidate sequences by

$$\text{score}(y) = \frac{1}{|y|^{\alpha}} \sum_{t=1}^{|y|} \log P(y_t \mid y_{<t}, x)$$

where $\alpha$ is the length penalty ($\alpha = 0$ means no normalization, $\alpha = 1$ means average log-probability per token). Machine translation systems commonly use $\alpha \approx 0.6$–$1.0$. The widget above uses $\alpha = 1$, which is why an early-ending beam can still compete with a longer one.

</details>

## Try it yourself

Take one prompt and generate three times: greedy, beam with $k=4$, and sampling at $T=0.9$ with top-p $=0.95$. Now judge them **twice** — once for "is this correct?" and once for "is this interesting?". Write down which setting won each column. That table is the entire decoding-strategy decision, and it is task-dependent rather than universal: the config that wins your translation eval will lose your chatbot eval.

## Recap 📌

- Decoding is search over a trained distribution, not part of the model — same weights, very different text
- Beam search (with length normalization) suits tasks with a right answer; past roughly $k=4$–$10$ it starts optimizing probability instead of quality
- Temperature, top-k, and top-p control how much of the tail you let in; open-ended generation needs sampling, and every generation needs explicit stopping rules
