# 3.5 — Debugging training: why is my loss NaN?! ⏱️ ~15 min

<Meme quote="It's not a bug — it's an undocumented feature." author="every engineer, seconds before finding the bug" />

## The hook

Regular code fails loudly: exceptions, stack traces, red text. Training fails *silently*: everything runs, no errors, and the model is garbage. Debugging ML is a different sport — here's your field guide, symptom by symptom.

## The symptom table 🩺

| Symptom | Prime suspects | First move |
|---|---|---|
| Loss = **NaN** | lr too high; log(0) or division by zero in loss; exploding gradients | Cut lr 10×; check loss inputs |
| Loss **flat from step 0** | lr ≈ 0; frozen weights; broken labels; dead ReLUs | Overfit-one-batch test (below) |
| Loss falls, **accuracy random** | Wrong loss function; labels misaligned with inputs; metric bug | Print 5 (input, label, prediction) triples and *look* |
| Train great, **val terrible** | Overfitting (3.2/3.3); or data leakage / duplicated rows | Check the gap; audit the split |
| Works locally, **garbage on MPS/GPU** | Model and data on different devices; dtype mismatch | Print `x.device, x.dtype` everywhere |

## The one weird trick: overfit a single batch 🎯

The most powerful ML debugging tool known to science:

```python
x_small, y_small = next(iter(loader))       # ONE batch
for step in range(500):
    loss = loss_fn(model(x_small), y_small) # train on it, over and over
    loss.backward(); optimizer.step(); optimizer.zero_grad()
```

A healthy network **must** be able to memorize one batch — loss should crash toward 0 (yes, we're weaponizing overfitting as a diagnostic).

- Loss → 0? Model + loss + optimizer are wired correctly; your problem is data or scale. ✅
- Loss stuck? The plumbing itself is broken — bug is in model/loss/optimizer wiring. You just cut the search space in half.

## The pre-flight checklist ✈️

Before any long training run:

1. **Overfit one batch** — plumbing check (2 minutes, saves days)
2. **Print shapes** of a batch through the model — silent shape bugs love broadcasting
3. **Look at 5 raw examples** with your eyeballs — is label 3 actually a cat?
4. **Start with a known-good lr** (`1e-3` + Adam) before exploring
5. **Log validation loss from epoch 0** — you can't diagnose what you didn't record

## Recap 📌

- Training fails **silently** — your tests are loss curves, not stack traces
- **Overfit-one-batch** is the single best diagnostic: separates plumbing bugs from data/scale problems
- NaN ≈ lr too high (usually); flat-from-start ≈ wiring; train/val gap ≈ memorizing
