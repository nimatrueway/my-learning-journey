# 1.2 — Learning = adjusting knobs ⏱️ ~12 min

<Meme quote="I have not failed. I've just found 10,000 ways that won't work." author="Thomas Edison — accidentally describing gradient descent" />

## The hook

Last lesson you turned the knobs by hand. Cute. But GPT has 1.8 trillion knobs — nobody's hand-turning those.

So how does a network turn its **own** knobs? With one dumb-but-brilliant trick you're about to break repeatedly.

## The idea: roll downhill ⛰️

Imagine a score called **loss**: *how wrong is the network right now?* Big loss = very wrong. Zero loss = perfect.

Plot loss for every possible knob value and you get a landscape — hills (bad knob settings) and valleys (good ones). **Learning is literally: put a ball where you are, and roll downhill.**

Each step:

1. Feel the slope under your feet (the **gradient**)
2. Take a step downhill
3. Repeat until it's flat

Step size is the **learning rate**. And that's where things get fun.

## Play with it 🎮

Hit **train** and watch. Then start breaking it:

<GradientDescentViz />

**Things to try (do all three):**

1. **learning rate ≈ 0.05** → tiny careful steps. Safe, but slow. Also: it settles in the *first* dip it finds — not necessarily the deepest one. Lazy, but honest.
2. **learning rate ≈ 0.5** → nice big confident steps. Fast *and* stable. Chef's kiss.
3. **learning rate ≈ 2.3** → 💥 the ball overshoots the valley, bounces higher and higher, and launches into orbit. This is a real failure mode called **divergence** — your loss becomes NaN and your afternoon is ruined.

## The tiny code version

The exact same thing, in PyTorch, 10 lines:

```python
import torch

w = torch.tensor([6.5], requires_grad=True)      # the knob, start way off
optimizer = torch.optim.SGD([w], lr=0.5)          # the "roll downhill" engine

for step in range(50):
    loss = 0.08 * w**2 + 0.6 * torch.cos(1.4 * w) + 0.6   # how wrong are we?
    loss.backward()                               # feel the slope
    optimizer.step()                              # take a step downhill
    optimizer.zero_grad()                         # forget the old slope

print(w.item())  # settled in a valley
```

Every neural network you'll ever train — from this toy to GPT — uses exactly this loop. Bigger landscape, same ball.

Run it yourself: open `notebooks/module-1-training-loop.py` in this repo — it includes an MPS check for your Mac.

<details>
<summary>🤓 The actual math (optional — skip freely)</summary>

The **gradient** is just the slope of the loss at your current knob value — the derivative $\frac{dL}{dw}$. Positive slope means "loss increases if $w$ increases," so you should step the other way.

Each training step applies the **update rule**:

$$w \leftarrow w - \eta \cdot \frac{dL}{dw}$$

Reading each symbol:

- $w$ — the knob (weight)
- $\eta$ (eta) — the learning rate, your step size
- $\frac{dL}{dw}$ — the slope: which way is uphill, and how steep
- The minus sign — "go *downhill*, not up"

With many knobs, the slopes for all of them are collected into a vector called the **gradient**, written $\nabla L$. Same rule, just applied to every knob at once:

$$\mathbf{w} \leftarrow \mathbf{w} - \eta \, \nabla L$$

Why the explosion at high $\eta$? If the step is bigger than the valley is wide, you land on the *opposite wall, higher up* — where the slope is even steeper, so the next step is even bigger. Repeat → infinity. That's divergence.

</details>

## Recap 📌

- **Loss** = a single number scoring how wrong the network is
- **Gradient descent** = repeatedly step downhill on the loss landscape
- **Learning rate** = step size: too small is slow, too big literally explodes
